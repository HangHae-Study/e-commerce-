# 부족한 백엔드 개발 인사이트를 위해,

### 교육을 들은 이유
- 나에게 부족한 점 
  - 현재 회사에서는 웹 개발을 전문적으로 하지 않고, 관련 프로젝트 경험이 적다 보니, 실제 개발 회사에서는 어떤 방식으로 코드와 프로젝트 구조를 설계하고 구현하는지 궁금했습니다.
  

- 교육에서 얻고자 하는 목표
  1. 최근 MSA 환경의 확장으로 인해, 대규모 트래픽 핸들링을 위한 기본 역량
  2. 소프트웨어 아키텍처를 통한 프로젝트 관리의 용이성
  3. 테스트 코드를 기반으로 한, 명확한 명세와 설계


- 교육에서 중점으로 집중한 내용
  - 기존 쿠버네티스를 통해 클라우드 네이티브 환경을 통한 프로젝트 및 인프라 설계 경험이 있엇습니다.
  - MSA 는 서비스간 통신을 위해, 이벤트/API 등 여러 방식이 존재한는데 이 과정에서 `"도메인 간"` 결합과 분리를 어떻게 설계하고, 서비스를 운용할지 고민할 수 있는 시야를 얻고자 하였습니다.


- 교육에서 얻은 내용의 활용도
  - 기본 적인 코드 아키텍처를 어떻게 가져가야, 추후 서비스 확장에 도움이 될 지 고민할 수 있는 시야를 얻게 되었습니다!
  - 특히 이벤트나, 외부 메모리를 활용하여 서버에 부하가 발생할 수 있는 부분들을 비동기적으로 처리하고, 보상할 수 있는 방법들을 고민하면서, 서버 구조와 설계를 동시에 할 수 있는 최소 역량을 갖추게 되었습니다.!



> 전체적인 교육이 끝나고 회고 하는 형태로 다시 포트폴리오를 작성하면서, 복기 및 정리를 한 내용입니다.
> - 교육 당시에는 시야가 좀았지만, 더 넓어진 시야로 당시에 생각을 스스로 피드백하면서 좋았던/부족했던 점을 한번 살피며 작성하였습니다.
