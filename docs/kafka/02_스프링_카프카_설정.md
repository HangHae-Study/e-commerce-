

### Spring for Apache Kafka
- 스프링에서 카프카 베이스의 메세징 솔루션
- 상위 레벨 추상화인 template을 활용하여 메세지를 발송
- `@KafkaListener` 어노텡이션을 기반으로, 메세지-기반 POJO 및 리스터 컨테이너를 제공
- 해당 라이브러리는 의존성 주입 및 선언을 담당해줌

### 환경 셋팅
의존성 주입 : `implementation 'org.springframework.kafka:spring-kafka:3.3.1'`
->  스프링 카프카 사용

---
### 카프카 도커 설정
```dockerfile
version: "3.9"

services:
  zookeeper:
    image: confluentinc/cp-zookeeper:7.6.1
    container_name: zookeeper
    ports:
      - "2181:2181"
    environment:
      # 클라이언트 접속 포트(브로커가 여기에 붙음)
      ZOOKEEPER_CLIENT_PORT: 2181
      # ZK 내부 타임 유닛(ms). 세션/심박 주기의 기준.
      ZOOKEEPER_TICK_TIME: 2000
    healthcheck:
      test: ["CMD-SHELL", "echo ruok | nc -w 2 localhost 2181 | grep imok"]
      interval: 10s
      timeout: 5s
      retries: 10

  kafka:
    image: confluentinc/cp-kafka:7.6.1
    container_name: kafka
    depends_on:
      zookeeper:
        condition: service_healthy
    ports:
      # 호스트에서 접속용(EXTERNAL)
      - "9094:9094"
      # (선택) 내부용(컨테이너 간) 포트도 매핑해두면 디버깅 편함
      - "9092:9092"
    environment:
      # 브로커 고유 ID (클러스터 내 유일)
      KAFKA_BROKER_ID: 1

      # ZooKeeper 접속 정보(브로커가 메타데이터 등록/조회)
      KAFKA_ZOOKEEPER_CONNECT: zookeeper:2181

      # 리스너 이름 ↔ 보안 프로토콜 매핑 (둘 다 평문)
      KAFKA_LISTENER_SECURITY_PROTOCOL_MAP: INTERNAL:PLAINTEXT,EXTERNAL:PLAINTEXT

      # 브로커가 실제 바인딩할 주소:포트 (이름은 위 매핑의 키여야 함)
      # - INTERNAL: 컨테이너 네트워크 내 접근(kafka-ui 등)
      # - EXTERNAL: 호스트 OS에서 접근(내 PC/로컬 IDE)
      KAFKA_LISTENERS: INTERNAL://0.0.0.0:9092,EXTERNAL://0.0.0.0:9094

      # 클라이언트에게 "이 주소로 붙어"라고 광고하는 주소 (매우 중요)
      # - 컨테이너들은 kafka:9092 로
      # - 호스트는 localhost:9094 로
      KAFKA_ADVERTISED_LISTENERS: INTERNAL://kafka:9092,EXTERNAL://localhost:9094

      # 브로커-브로커 내부 통신은 어떤 리스너를 쓸지 지정
      KAFKA_INTER_BROKER_LISTENER_NAME: INTERNAL

      # 단일 브로커이므로 복제/ISR 1로 (운영 다중 브로커는 3 권장)
      KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR: 1
      KAFKA_TRANSACTION_STATE_LOG_REPLICATION_FACTOR: 1
      KAFKA_TRANSACTION_STATE_LOG_MIN_ISR: 1

      # 개발 편의: 자동 토픽 생성, 기본 파티션 수
      KAFKA_AUTO_CREATE_TOPICS_ENABLE: "true"
      KAFKA_NUM_PARTITIONS: 3

      # 컨슈머 그룹 초기 리밸런스 지연(개발 편의로 0)
      KAFKA_GROUP_INITIAL_REBALANCE_DELAY_MS: 0

    healthcheck:
      test: ["CMD-SHELL", "kafka-topics --bootstrap-server localhost:9092 --list >/dev/null 2>&1"]
      interval: 10s
      timeout: 5s
      retries: 10

  kafka-ui:
    image: provectuslabs/kafka-ui:latest
    container_name: kafka-ui
    ports:
      - "8080:8080"
    environment:
      # 컨테이너 네트워크 내부 주소로 붙는다(INTERNAL 리스너)
      KAFKA_CLUSTERS_0_NAME: local
      KAFKA_CLUSTERS_0_BOOTSTRAPSERVERS: kafka:9092
    depends_on:
      kafka:
        condition: service_healthy
```

### Spring Kafka 프로퍼티
```yaml
  kafka:
    bootstrap-servers: ${KAFKA_BOOTSTRAP:localhost:9094}

    producer:
      acks: all
      retries: 10
      properties:
        enable.idempotence: true
        max.in.flight.requests.per.connection: 5
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.springframework.kafka.support.serializer.JsonSerializer

    consumer:
      group-id: order-service   # 주문 서비스가 결제 결과를 받는 컨슈머라고 가정
      enable-auto-commit: false
      auto-offset-reset: latest
      key-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      value-deserializer: org.springframework.kafka.support.serializer.JsonDeserializer
      properties:
        spring.json.trusted.packages: "*"
        spring.json.value.default.type: "com.example.events.PaymentResultEvent"

    listener:
      ack-mode: manual          # 수동 커밋(정확한 처리/재시도 제어)
      missing-topics-fatal: false
```

- acks: all: 브로커 리더 + ISR 동기 복제까지 확인 후 성공 처리 → 내구성↑

- retries: 일시 오류 재시도

- enable.idempotence: true + max.in.flight=5: 중복 전송 방지(프로듀서 레벨 정확히 한 번)

- JsonSerializer: DTO를 JSON으로 직렬화

- spring.json.add.type.headers: false: Type 헤더를 빼서 이종(타 언어) 소비 호환성↑

- group-id: 같은 그룹이면 파티션을 나눠 소비(스케일 아웃).

- enable-auto-commit: false: 수동 커밋으로 전환(비즈니스 처리 성공 후 커밋)

- JsonDeserializer: 프로듀서가 JSON으로 보낸 걸 DTO로 역직렬화

- trusted.packages: 역직렬화 허용 패키지(예시로 전체 허용 *)

- value.default.type: 2번에서 타입 헤더를 뺐으므로, 여기서 받을 DTO 타입을 고정
  → 예: com.example.events.PaymentResultEvent

- ack-mode: manual: 리스너 코드에서 ack.acknowledge() 호출 시 커밋

- missing-topics-fatal: false: 토픽이 (아직) 없다고 부팅 실패하지 않음

- 동시성(concurrency) 은 빈 설정 혹은 @KafkaListener(concurrency="N")**로 조절
- setConcurrency(N) = 같은 JVM에서 N개의 Consumer 스레드(=N개 인스턴스) 실행
